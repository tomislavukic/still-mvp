# Phase 7 — Company Network and ownership-native commerce

Date: 2026-08-13

## Production model

Phase 7 connects a verified CompanyOS organization to a buyer-controlled Thing without turning Still into a merchant of record. The normalized chain is:

`Company Product → Variant → live inventory balance → Offer → Order → confirmed ownership Passport → permissioned relationship`

Products, variants, policies, offers, orders, order items, relationships, marketing consent, secure claim tokens, owner requests, product notices, audit events and plan configuration are stored in additive `company_network_*` D1 tables. Existing CompanyOS identity, membership, verification, inventory, buyer identity, ownership Passport, World, Needs, Market, Professional and Service Network records remain canonical in their respective domains.

## Buyer journeys

- BUY, FIND and REPLACE Needs may show deterministic company offers after World-first resolution options. Every match exposes recorded reasons and uses real available stock.
- Wanted Objects retain their C2C matches and may also show matching verified-company offers. No paid or sponsored ordering signal exists.
- A pre-purchase Passport exposes company-declared product identity, condition, live availability provenance, price, warranty and return policy before the buyer leaves for an external checkout.
- Compare With Mine checks confirmed identifiers in the buyer's existing World before encouraging another purchase.
- An external order starts with payment status `NOT_RECORDED`. Only an authorized company member can confirm it, and a real payment or invoice reference is required.
- A confirmed order creates the canonical ownership Passport and World profile. It also establishes a granular relationship whose support, warranty, service-history and product-update permissions remain under buyer control. Marketing consent is separate.
- Buyer support, warranty and return requests and company replies are durable, tenant-scoped records and appear in World/NOW only when they exist.

## CompanyOS journeys

The authenticated Company Network workspace is mounted inside CompanyOS and provides real operations for:

- public verified company projection;
- normalized product catalogue and variants;
- warranty, return and support policies;
- inventory-backed offers;
- external order evidence and confirmation;
- support, warranty and return handling;
- cryptographically random single-use Passport claim QR codes;
- verified product and safety notices;
- plan and billing-availability truth.

The legacy simulated Company Commerce UI is not loaded. Existing CompanyOS tools and APIs remain available.

## Payment and inventory truth

- An offer references existing `inventory_items`, `inventory_locations` and `inventory_balances`; it does not maintain a second stock count.
- Creating an order reserves stock atomically. Confirmation reduces on-hand and reserved stock and records an inventory movement. Failed persistence and expired reservations release the reservation.
- External checkout opens only an HTTPS company URL. Still records intent, then waits for explicit company evidence.
- Still-hosted checkout is refused unless a real configured provider is available. The old demo-completion route returns HTTP 410, and the legacy checkout can no longer manufacture a demo order.
- Seller verification is derived from the current organization state, never a hardcoded `true` value.

## Secure claims and duplicate handling

Claim tokens contain 32 random bytes and are shown once. Only the SHA-256 hash is persisted. Claims expire, are single-use and update atomically. Public resolution returns only a bounded verified product projection.

Before creating a Thing, Still compares serial number and GTIN with the owner's existing Passport records. A possible duplicate is not silently merged or duplicated: the owner must explicitly link the verified identity to the existing Thing or stop.

## Deliberately unavailable

- No Still-hosted payment, subscription activation or merchant-of-record claim is shown while billing/provider configuration is unavailable.
- No stock, seller verification, price, order completion, support event, rating, ranking or product fact is simulated.
- No arbitrary product scraping or generated product data is used.
- The configured Still for Business plan is visible, but its subscription status remains `NOT_CONFIGURED` until real billing exists.

## Deployment and migration

The active entrypoint is `merchant-backend/worker-v138.js`. It extends the Phase 6 Worker chain and lazily applies the additive Phase 7 schema for deployment compatibility. The reference migration is `merchant-backend/schema-v138.sql`. No existing tables, bindings, D1 identifiers or R2 identifiers are removed or renamed.

Production assets are generated by `build-public.js`. Deployment continues through the existing Cloudflare Workers Git integration from `main`; no parallel deployment workflow or new Cloudflare credential is introduced.

## Validation

`npm test` contains more than 45 Phase 7 architecture, security and UI assertions plus real isolated Wrangler/D1 journeys covering products, inventory, policies, offers, Needs, Wanted, external order evidence, canonical Passport creation, permissions, requests, notices, secure claims, replay prevention and explicit duplicate linking.
